# Joint discourse x semantic analysis (RQ2)

Downstream of two finished layers, neither of which is modified here:

* the native-discopy explicit-relation table (`discourse_parser/
  discopy_explicit_candidates.csv`, `is_connective == True`, 5,504 relations),
  frozen 2026-08-27;
* the frozen DeepSeek semantic annotations
  (`results/justification_annotation/full_frozen/annotations.jsonl`).

Generated by `notebooks/04_justification_analysis/9_final_joint_discourse_semantic.ipynb`
over `src/justification_analysis/joint/`. Do not edit by hand: re-run the notebook.

## The question, and its limits

*Which explicit discourse relations tend to occur in sentences containing each
semantic category?*

The parser identifies explicit connectives and their PDTB sense. It does
**not** recover discourse arguments. Everything here is therefore a
**sentence-level association between the form of a sentence and the kind of
information it carries** - never evidence that a connective attaches to a
semantic proposition, that a relation "expresses" a category, or that a
category is an argument of a relation.

## Alignment

Both layers carry `(model, game_id, run_label, sentence_id)`, because the
parser was run over the same fixed segmentation the annotator saw. The join is
on those identifiers and is then **verified** by comparing the sentence text
the parser scored against the canonical sentence text byte for byte. All 5,504
accepted relations align to exactly one canonical sentence; none required
fuzzy matching and none failed.

## Conventions

Unit is the canonical sentence; **presence, not counts** (a sentence with two
Contingency relations counts once). Each run computed independently, then mean
and SD across the three stochastic runs; greedy is one run, kept separate, SD
NaN. Bootstrap: 10,000 replicates, seed 20260826, percentile 95% CIs, games
resampled with all runs and sentences attached and the same ids across models,
no p-values. **Lift is descriptive and is not bootstrapped.**

`Other` is excluded from the comparative analysis (0.3% of labels); it appears
only in the integrity checks.

## Thin support - read this before interpreting anything

`P(r|c)` is only as good as `N(c)`, and several model-category combinations are
very thin at sentence level:

| combination | mean sentences per run |
|---|---|
| E2B Mechanical | 6 |
| E4B Mechanical | 15 |
| E2B ClaimComparison | 17 |
| 31B Uncertainty | 22 |

These are **flagged** (`support_is_thin`, threshold 30/run) and hatched in the
figures, never dropped - deleting them would hide which combinations the corpus
cannot speak to. Nothing hatched should be interpreted, and the largest
greedy-vs-stochastic disagreements all fall in these cells.
