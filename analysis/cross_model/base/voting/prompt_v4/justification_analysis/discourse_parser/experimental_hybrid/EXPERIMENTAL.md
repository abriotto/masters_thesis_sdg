# EXPERIMENTAL — DiMLex-expanded hybrid. REJECTED. Not production data.

Nothing in this directory may be read by production analysis, and no relation
from it may be merged into `../discopy_explicit_candidates.csv`.

## The architecture that was tested

    candidates = discopy's own candidates ∪ DiMLex candidates discopy never
                 enumerated, then the SAME unchanged classifier decides
                 everything

Attractive because it separates concerns cleanly: DiMLex broadens coverage,
discopy alone makes every contextual judgement. No per-form rule, whitelist or
blacklist was applied — that was the point.

## Why it was rejected

Manual validation of 25 cases: only **4/18** accepted forced spans were genuine
connectives. Four lexical forms failed systematically — `eventually` 0/5, `with`
0/4, `upon` 0/2, `without` 0/2 (0/13 combined) — while 0/5 NoSense controls were
wrongly rejected.

The gain was modest anyway: 5,504 → 5,757 relations (+4.6%), per-100-word rates
moved ≤0.16, class profiles ≤1.8 points, and **no model ordering changed**. The
hybrid would have bought a cleaner story at the cost of measurably worse
connective identification.

**Do not reopen this decision, and do not add handcrafted lexical exceptions.**
